# New Thread Templates architecture

Definitions and unfinished editor drafts are workspace shared and collaborator editable. Identity records attribution; there are no product roles or custom ACLs. `model.ts` is the shared product schema and pure validation/interpolation implementation. `rpc-contract.ts` exports `templatesContract` (alias `contract`), all wire schemas, and `TEMPLATES_CHANGED` invalidation topic. Tokens are `{{field}}` or `{{field|literal fallback}}`; scripts and expression evaluation are unsupported.

## UI consumption

- `catalog({})` returns entries with independent `draft`, `published`, and monotonic `latestRevision`. `saveDraft({definition,expectedGeneration})` uses null only for a new record. Existing edits require the current generation. Publication copies a validated draft into an immutable revision, leaving draft and previous published revisions intact. Unpublish removes the chooser pointer without deleting historical launch data. Duplicate creates a new shared draft.
- `remove({templateId,expectedGeneration,expectedRevision,expectedLatestRevision})` compares the exact current draft generation (nullable), published revision (nullable) and latest revision in one immediate transaction with the issued shared actor commit guard. Its receipt is `{templateId,removedAt,removedBy}`. A collaborator edit, publish, unpublish or publish/unpublish cycle invalidates a stale removal. Same snapshot replay returns the original removal time/attribution. A durable tombstone hides the template from catalog/get while retaining the original shared entry, immutable revisions, personal drafts and launch journal. The ID remains permanently reserved; stale saves, including generation-null, cannot recreate it. There is no restore or hard-delete API in this composition. Existing journal-first recovery and safe pinned preparation retries survive removal; new operations reject because no live publication remains. Removing never creates a native effect.
- `context({projectId?,environmentId?,hostId?})` returns real projects, enrolled hosts, native environments, routed model choices and current captured actor/session. `preview({definition,inputs,projectId?})` validates and resolves through the same code as launch, without create/spawn. For new projects it first detects an existing host/path source and previews that actual project's name/defaults with createsProject=false. Otherwise it previews the requested source and target-host catalog; final project defaults are resolved again after native creation. `primaryHostId` is exposed for editor picker routing, matching native project-default policy. Preview is advisory, with no side effects or dispatch token. Show fresh preview before enabling Start.
- Personal form drafts use exported `inputDraftResource` with `useBbIdentityClient` -> continuously mounted shared Provider -> Context -> `useIdentityStateBinding`, recordId = template id. Server binding registers self-only writes and collaborator reads. Captured owner/session belong to the package controller; changing view does not retarget writes. Persist operationId + revision before invoking launch. Definitions/editor drafts are intentionally shared RPC/CAS storage, not person-scoped resources.
- `launch({operationId,templateId,revision,inputs,projectId?,expectedActor,expectedSession,nativeSubmission?})` pins a published immutable revision and immutable fingerprint. `launchStatus({operationId})` reconciles only and never dispatches. A failed *pre-effect* operation with retryable=true may resume through launch with the SAME operation identity and exact input. The fingerprint covers operation/template/revision/input/project/captured actor and the complete native submission when present; expectedSession is a current lifecycle precondition. Same-actor pre-effect resume may supply a fresh session while the original journal session/actor stay historical. Changed inputs require a new operation. Unknown outcomes always remain check-only. A duplicate request cannot claim an effect again. Native confirmed threadId is the navigation receipt.
- `recentLaunches({offset?})` returns {launches,nextOffset}, 50 actor-scoped journal snapshots per page; list history remains reachable after unpublish. Each snapshot includes immutable revision, status, requested project and recorded effects. Normal phase `rejected` proves a local pre-effect rejection; stale context/nonexistent revision may return that without a journal. A lost response followed by null status remains uncertain, not permission to resend.
- Subscribe to `TEMPLATES_CHANGED` for authoritative refresh; successful refresh clears matching read errors. No feature refresh timer or background detached promise owns work. Current-generation public thread lifecycle listeners filter plugin origin, read metadata for that one known thread, and join the existing operation/fingerprint/revision/template/actor/inputs. Created events remain provisional. Only later active/idle evidence may confirm the same stable claimed spawn receipt. A semantic journal change publishes invalidation. There is no history scan or dispatch and no success inferred from matching metadata alone; deleted/no-match/unavailable metadata cannot promote a receipt. The handler rechecks generation lifetime after its await, and listeners retire with the host generation.

## Optional full BB editor

The ordinary form still sends directly. Existing-source dedup qualifies. Form/context updates never silently reseed edited native work. A nonconfirmed/stale onSubmit throws so native draft storage does not clear. No main composer write or browser-side spawn is used.

Native mode validates pinned template/fields, then the actual selected existing project, environment and execution. Structured `input[]` remains an array with mention ranges/resources, commands, attachment host/sourceProjectId/path and visibility intact; it is never flattened for spawn. The journal and recent history retain the complete submission. Native project/environment/provider/model/reasoning/permission/serviceTier/sessionOptions/executionInputSources and optional integer sendAt pass unchanged, with the original generated title. Known-host/reuse routes validate target catalogs, permission ceilings and provider support before claim. Native default inputs retain their actual provenance rather than receiving template-generated provenance.

For provider-created future machines, owner accepted deferred native model/permission admission. Public provider registration, selected machine provider and composition linkage are checked; existing-host availability maps are keyed by host ID. No primary-host catalog is treated as future-target evidence, no alternative model is substituted and no host ID is invented. Recorded effects mark `mode:native`, `validation:deferred-native`, hostId/routing null and the exact native environment. Native admission failure or lost response retains the same immutable request/inputs and unknown effect claim. Native permissions remain authoritative.

## Durable launch boundary

SQLite is the smallest durable owner. The launch row contains immutable definition revision/snapshot, normalized inputs, original request fingerprint, full package-issued ActorSnapshot, captured expected session, creation intent, completed project ID, exact native spawn request, claim phase, and resulting thread ID. One immediate transaction claims preparing; compare-and-swap claims `project-claimed` BEFORE `projects.create` and `spawn-claimed` BEFORE `threads.spawn`. A second process/request sees the durable claim and cannot perform the effect. Stable projectClaim/spawnClaim values identify completed effects independently of the generation token. That token fences old continuations before further effects; disposal prevents the old lifecycle from claiming any further effect. Late receipt completion can record only the claimed effect and cannot progress to a new effect after disposal.

`projects.create` supports only an enrolled host + existing absolute local source path. No remote bootstrap/shell scripts. The native implementation finds-or-creates a project by host/native-normalized local source path. On lost create response, reconciliation lists matching sources and requires a unique exact source match, ignoring display name. No match/ambiguous evidence remains project-unknown; no blind create is permitted. Confirmed project ID is committed before execution/spawn preparation and survives failure.

Execution inherits from the FINAL project. Reuse environments are validated against project and host; local-source/worktree policies map to native environment objects. Models and reasoning/service tiers are validated on that environment/host. Explicit supplied execution fields receive `executionInputSources: explicit`. Permission mode is never elevated by Templates; native project/default policy remains authoritative.

## Saved machine selection

Existing-project and choose-at-launch destinations optionally store `hostId`. Omission preserves historical behavior and serialized definitions: automatic project-default uses BB's primary machine; existing explicit checkout/worktree policies without a host keep their prior source selection. New-project retains its single required source `hostId`, with no separate conflicting machine option. A specified existing/choose machine plus project-default is structurally saveable as an unfinished draft but cannot publish, preview or launch. Public project-default has no host override and natively chooses checkout/worktree on the primary machine, so choosing a particular machine requires an explicit source-checkout or worktree decision. Reuse always uses its actual environment host and rejects a conflicting saved machine.

For a specified machine, the resolver validates connection, selects that project's exact source on that machine, checks the selected source directory through one public hosts.directory request and routes model preflight to that machine/project. Missing source, removed/regular-file directory, unavailable host/catalog/model blocks before native claim; no fallback host, arbitrary path or bootstrap is introduced. New-project existing-source dedup also checks the actual retained directory before offering a seed or claiming a spawn. Newly provisioned sources retain their existing directory/create/final-defaults checks. Preview/effects/direct spawn and the native opening seed use the same resolved host/environment; revisions and journal snapshots preserve the saved host across edits/reload.

Native editor opening revalidates the saved host/source at that moment. The public full editor may subsequently apply its own visible availability fallback, and normalizes a nonnull unmanaged seed path to its supported project checkout selection. An opening seed therefore is not an immutable native machine pin: the actual visible native submission remains final and is validated/preserved as described above. No private native selection hooks are used to override this behavior.

The native spawn request seeds plugin metadata containing operation id, fingerprint, revision, captured actor evidence and immutable input snapshot IN the creation call. Native creation first inserts a provisional pending row and may subsequently reject/delete it. Matching metadata or `thread.created` therefore records only a candidate, never navigation success. A known successful native API acknowledgment confirms creation, including accepted queued/pending work. Without that acknowledgment, only a matching retained active/idle thread can confirm admission; pending/starting/error remains check-only. Deleted candidates are durably tombstoned to fence stale lifecycle observations. Stable late acknowledgment and rejection can record only the same claimed effect across generation replacement; old continuations cannot claim another effect.

No match, a timeout, host restart, a cancelled request, or a deleted/unlisted native thread cannot prove that a prior dispatch will never commit. `spawn-claimed` / indeterminate is NEVER re-spawned. No exactly-once native guarantee is claimed. Reconciliation is request-owned on status/load/explicit retry; no detached timers or promises are durable owners. If native receipt cannot be found the UI reports indeterminate honestly and preserves inputs and any project. An acknowledgment lost for accepted queued/pending work cannot be proven from its pending row alone. Separately, an old-generation acknowledgment received and saved after plugin reload has no supported current-generation notification seam: owner accepted that Check status or reopening may be required to display this durable success until a later active/idle event. The exact factory-replacement test preserves this coverage limit rather than converting provisional creation to success or introducing polling.

Inputs are capped at 64 KiB total UTF-8 JSON, rendered prompt at 256 KiB, structured native submission at 1 MiB and seeded metadata at 240 KiB (below native 256 KiB). Native mention offsets must be ordered, non-overlapping and within their text; resources and attachment DTOs use strict validated shapes. Interpolation checks expansion during substitution. Empty rendered titles are omitted for native automatic naming; request validation/budget failures occur before spawn claim. Explicit default service tier is always valid, provider/model options are intersected, and disabled fast tiers block explicit non-default selection.

## Optional Inbox assignment

New eligible-person launches retain a separate immutable assignment intent under `new-thread-templates:<launch UUID>` and the captured actor. Old journals have no intent and are never backfilled. Native creation remains succeeded/Open if Inbox is absent, incompatible, timed out or rejected; assignment is optional and does not change native plugin/machine authorship.

The live originating request may make one bounded automatic claim after a native ACK (including accepted queued pending), or after accepted active/idle recovery plus a fresh nondeleted root read. `thread.created`, provisional/pending metadata, unknown or removed creation never authorizes assignment. Current creation evidence is checked again inside the durable dispatch update after all preflight awaits. A disposed generation/expired actor cannot reuse its person to dispatch after a late ACK; only creation facts are stored. A new request from the original person may Check, then explicitly retry the same conditional assignment operation. New actors, view-as and machine fallback do not retarget it.

Inbox owns the documented V1 conditional claim/lookup protocol; the consumer duplicates only its bounded DTO codec/constants in `inbox-assignment-contract.ts`. It never imports provider implementation/storage, calls `setOwner`, scans owner history, or retries spawn. `assignment.receipt` is historical; `assignment.current` is authoritative ownership observed at that response. Terminal receipts are immutable, current revisions never regress, and late absent responses cannot make a terminal claim retryable. An initial claim can be followed by manual Unassign without replay restoring ownership.

Local waits are describe1000/lookup1000/claim2500 ms, plus fresh thread read2000 ms. Canonical parsed-response UTF-8 is capped at64KiB before decoding; this cannot bound transport's earlier allocation. The whole attempt is singleflight and each timed-out raw call retains its local slot until it actually settles. Signal cancellation is not remote non-execution. Replacement generations may overlap only the SAME provider-idempotent operation. There is no durable background actor capability or global runner.

Shipped consumer tests use the real Templates factory, journal, identity binding and scoped nested transport with a scripted public provider; this does not prove Inbox transactions. Organization-local tests exercise the actual Inbox factory/migrations/SQLite. ## Saved request interruption and explicit resume

A new personal draft saves `launchCheckpoint:{version:1,request:LaunchRequest}` before either direct or native launch RPC. The checkpoint pins the original operation UUID, actor key, template/revision, inputs, optional requested project and exact optional native submission. `resumeLaunch({checkpoint,expectedActor,expectedSession})` requires the fresh live original actor/session and refreshes only the session precondition, which is excluded from the business fingerprint. Existing journal requests and captured actor facts remain unchanged. It never rebuilds a request from the current form/template or allocates a new operation. An absent journal is not proof of non-dispatch: explicit same-operation replay relies on the same atomic journal insertion and pre-effect claims even if the original request arrives concurrently. Claimed/unknown native effects reconcile without dispatch; definite pre-effect failures may resume under their original snapshot. A missing current publication with no journal produces a definite rejection; an existing journal remains recoverable after edit/unpublish/removal.

Legacy saved references without this exact checkpoint and without a server journal remain check-only. Their original request cannot safely be recovered from current inputs/template or a native draft alone. Preserve those inputs/native work and explain that limitation; never synthesize a replacement request or treat null lookup as permission to clear it. The owner explicitly accepted this legacy boundary. Existing historical journals retain their normal status/history recovery.

## Startup and History bounds

Startup recovery selects and iterates only `preparing`, `ready`, `project-claimed` and `spawn-claimed` through a partial phase index. Completed, failed and already-unknown rows are not decoded or rewritten. Stable effect claims remain intact while the generation token rotates. An actor/date/id index serves History ordering. Creating each new index entails a one-time SQLite index build; ordinary later activation does not re-decode all completed journals.

History returns at most50 complete records with a4MiB serialized JSON page target, iterating until that byte target or count limit. `nextOffset` advances by the number actually returned, not a fixed50. Inputs, revision/definition, effects and exact native submission are never truncated or deleted. A single pre-existing valid record can itself exceed the target because historical authored definitions are not retroactively capped: that record is returned alone with a usable next offset. This explicit individual-record exception preserves recovery without a pagination dead end. Tests cover large valid native requests, actor isolation, exact offset continuation, the oversized-record exception and SQLite query plans.

Inbox deletion now records durable negative evidence, clears current owners/override and advances ownership revision in one synchronous transaction before sticker-worker cleanup awaits. The immutable original assignment receipt remains available; current empty ownership persists even if the plugin stops during cleanup and reopens. This does not change the unrelated cost/HUD or native authorship boundaries.

Provider and consumer codecs are challenged separately with byte-identical static V1 JSON fixture matrices. These cover strict inputs, additive outputs, future versions/meanings, identity keys, receipt consistency, current Unassign and truncated owner bounds. Neither test imports the other product. This closes a codec-compatibility verification gap, not a previously demonstrated incompatibility, and does not establish public-registry SDK portability.
