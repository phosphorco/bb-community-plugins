# Turn result images

An independent native-image occurrence supplier using the public turn-results contract. It declares the exact `@phosphorco/bb-turn-results@0.1.1` dependency; canonical leaf verification compares the installed registry files with the reviewed archive. See the gallery README for the ordinary registry/development-SDK install and native-binding procedure. This dependency verification does not establish complete plugin or live acceptance.

Recognition uses only the bounded completed native image event, exact saved-path site and original selected digest. Resolution independently checks complete provider PNG bytes against an explicit-host file read, preserving unknown historical origin separately from verified current location. It considers one current host candidate for an unbound artifact and never moves an existing binding to another host.

Sparse source observations retain original identity, generation time/proof and verified materialization facts through native output pruning and restart. Missing files affect current availability; they do not retract generation. No image bytes, prompts or transcript are stored. Storage and source requests are bounded; expired/evicted source facts remain explicit limitations. There is no startup thread scan, detached indexing, polling or resend behavior.

The production factory registers the private `turnResultImagesV1Media` RPC in addition to the shared data protocol. The strict request is `{version:1, identity:ResultIdentity}`; callers cannot supply a host or path. The identity is a lookup claim, never proof. For an unresolved native-image candidate, one request rereads and admits the exact native carrier, hashes its complete provider PNG, selects one initial explicit host, and verifies the matching file before committing sparse facts in the existing source store. Only then can it create a native preview lease. A previously bound image always rehashes its original fixed host target; it never moves to a different current host. Fresh bound Media requests do not rewrite facts or extend retention. An expired or unavailable source observation is refreshed only after the same request successfully verifies the current fixed file; historical proof, materialization and target remain immutable. Initial admission may leave a valid committed fact if a later lease or consumer publication fails.

The exact response is one of:

```ts
{ version: 1, state: 'ready',
  lease: { targetFingerprint, leaseGeneration, baseUrl, url, expiresAtMs, resolvedAt },
  image: { mimeType: 'image/png', width, height, sizeBytes, sha256 } }
{ version: 1, state: 'unavailable', reason }
```

`targetFingerprint` is lowercase SHA-256 of canonical JSON `{target,sha256}`, using the stored host file target and independently verified provider digest. `leaseGeneration` is a fresh UUID per successful operation. URLs are origin-relative native `/api/v1/file-previews/<id>/<encoded-basename>` URLs; neither URL nor lease generation is an artifact identity or durable fact. The consumer owns its structural output codec and correlates the fingerprint with its admitted file route and hash. No cross-plugin source import or presentation registry is needed for an ordinary image.

Canonical input/output bounds are 8,192/16,384 bytes, including unknown fields before schema decoding. Image admission is at most 8 MiB decoded, 32,768 per dimension and 16,777,216 pixels. Initial native admission, provider decoding/hash, host lookup, file verification and preview creation share one 3,000 ms source deadline. Bound-image file rechecks and preview creation use that same deadline. This permits slower valid file verification at the cost of up to 1,700 ms longer occupation of an existing slot when verification fails; it does not add retries or relax verification. Media and resolve share two source request slots. Native leases request 120 seconds; expired, over-TTL or malformed responses are unavailable. There is no source lease cache, polling, automatic renewal or retry. Source disposal and deadline abort/fence local continuation even if an SDK call ignores cancellation. The public RPC context has no caller signal, so caller cancellation only fences the caller; source deadline/disposal remain independently enforced. An already created native lease cannot be revoked through the public SDK and expires under its TTL.

The gallery owns two media requests per window, at most 64 retained resource records, shared verified Blob URLs, visibility and reference-count cleanup. A settled speculative-only failure leaves one ordinary first-foreground opportunity; foreground failures require explicit retry. Warm remounts reuse verified Blobs without timer-based lease renewal or idle retry. A lease is a verified-file observation before creation, not an immutable snapshot of future GET bytes; the consumer must bound and hash the actual fetched bytes and validate decoded dimensions. A successful lease alone does not clear an image-load error.

The source tests exercise the actual server factory, public SDK fake host and real SQLite, including pruned-output reload, fixed-target hashing, bad lease responses, source capacity/deadline/disposal and unchanged durable rows. Exact original-PNG production-handler proof, independently reviewed complete adoption, published dependency adoption and live gallery composition remain required. Existing native probe evidence is separate from these source tests.

Run checks from the community repository with its declared Bun1.3.14. SQLite persistence/composition cases use Node and the actual public better-sqlite3-compatible handle, since that native addon is unsupported by the test Bun version. This is disclosed test routing, not a claim that Bun loads the addon. BB owns the production database handle and its disposal.

Gallery recognition leaves initial candidates unresolved, with no confirmed-generation or available-file claim. It skips the preliminary 1,300 ms image Resolve. After successful Media admission, normal Resolve returns the committed source facts; Gallery Apply and an actually issued retained-page read must agree on identity, target and SHA before any preview GET or Blob is adopted. This correlation and fetching remain inside the existing 7,000 ms consumer budget. There is no second admission request, detached worker, new endpoint or automatic foreground retry. The combined 3,000 ms operation can still time out; this is not a native latency guarantee. Ignored source-port promises retain their existing two-slot credit through actual settlement after a local deadline.
