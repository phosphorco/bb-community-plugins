# Shared JEV transport v1

This package owns bounded JSON DTOs and intended-owner RPC adapters. It owns no credential, storage, inference policy, admission gate, timer or retry engine. Root imports Zod only; `/bb` has SDK type imports only; `/testing` drives real adopter ports with caller-supplied inert work.

Topics (`jev-topics`) is the first explicit connection owner. Its existing secret setting remains local. `sharedJevDescribeV1(null)` advertises protocol `bb-jev`, versions, owner/configured metadata, the nonsecret setting field/source, supported named work and limits. A consumer uses listed plugin discovery for that explicit owner; absence/disabled/incompatibility is an operational error, never permission to scan credentials or switch owners.

`sharedJevSubmitV1` takes version1, exact namespace/operationId, consumer/work kind/opaque attribution, finite JSON wire, absolute deadline and response bound. Inputs are strict. A complete canonical SHA256 input fingerprint binds wire, work, attribution, operation, deadline and budgets. No URL/header/key parameter exists. Owner storage must reserve that immutable request before work and persist effect-possible before its fixed JEV HTTP POST. Same operation+input returns retained facts, changed input conflicts. Invoked or uncertain work must never be automatically relaunched, including after process/plugin restart. An interrupted effect-possible row becomes uncertain. Consumer policy/budget/evaluation ledgers remain consumer-owned.

`sharedJevLookupV1` takes version+exact operation and returns null or current record. Results are additive at evolving object boundaries. Opaque attribution/response JSON remains exact. States distinguish positive not-invoked from possible invocation, succeeded transport, failed transport and uncertain effects. Success is transport evidence, never semantic policy approval. Usage preserves provider-reported token counts and opaque reported cost (or null); missing/invalid usage remains explicit. No price or token estimate is invented. Raw response and bounded HTTP error context are retained, masking only the exact owner credential. Work attribution identifies MR admission/suite and their attempt/partition separately from Topics assessment work.

Package caps: request1MiB, raw response1MiB, response envelope1MiB+64KiB, describe16KiB, JSON depth48, max absolute execution budget60s and4 physical unsettled calls per client lane (submit, ordinary read, reconciliation read; maximum12 RPCs). Owner advertises/enforces its physical limit independently and retains a slot until HTTP/body work actually settles. Abort/timeout only fences a local observation; it does not establish non-execution. The adapter attempts at most ONE independent bounded lookup after failed submit, using separate reconciliation capacity so saturated writes cannot starve the first reconciliation wave. If that finite read capacity is also occupied, it refuses locally and retains unknown; it never retries submit. A lookup failure/null remains unknown.

No cancel-write method is provided in v1: cancelling an observer or MR evaluation cannot undo an already invoked HTTP call. The service owns its deadline and disposal abort. Late terminal HTTP observations may settle the owner's transport journal, while a retired MR assessment remains fenced by its own ledger.

Provider must preserve existing Topics scopes/assessment behavior and serve shared named work independently of an assessment profile. Initial named work is `message-rules.admission` and `message-rules.suite`. Dedicated MR override remains an explicit consumer selection and is not a service credential source.

Proof layers: package emitted/packed tests, real owner SQLite+RPC conformance, actual MR adopter ledger tests and loaded cross-plugin inference are separate. No package test establishes loaded runtime, native admission, provider execution or billing correctness.
