# Thread Attributes, package0.2.0 / filtering wirev1, valuesv1

Independent plugins register thread attributes once, supplying both filters and column values. Consumers discover and render them without plugin-specific code. A filter evaluates a bounded consumer-supplied thread census; it never widens that census, starts scoring, writes, or treats missing evidence as a negative fact.

| Supplier owns | Contract owns | Consumer owns |
|---|---|---|
| Attribute meaning, choice identity, storage, source access, personal lens, matching, row values and coverage | Wire schemas, fixed RPC names, bounds, version negotiation, owner-bound client, registration and conformance helper | Discovery, one attribute catalog, choices UI, columns, selected conditions, AND composition, loaded census, requests and honest result notices |

`threadFiltersDescribe(null)` advertises `{protocol:'bb.thread-filters', versions:[1], valueVersions:[1], dimensions:[{id,label,multiple,description}]}` for a combined attribute supplier. The exact same dimension IDs/labels generate filters and columns; there is no separate column registration. Legacy filter-only suppliers omit valueVersions. Decode the tolerant envelope before v1 details. Identities are `(listed plugin ID, dimension ID)`, never an advertised namespace. Installing another conforming supplier requires no consumer code changes.

`threadFiltersChoicesV1({dimensionId,viewerKey,query,cursor,limit})` returns `{choices:[{id,label}],nextCursor,revision}`. Choice IDs are opaque, stable within the dimension, and interpreted only by their owner. Cursors bind query/viewer/revision; a supplier rejects stale cursors. Consumer resets accumulated pages when revision changes. Query text searches all source choices. Stored selections retain labels when choices disappear and are never silently cleared.

`threadFiltersMatchV1({viewerKey,selection:{dimensionId,values,mode:'any'|'all'},threads:[{id,projectId,parentThreadId}]})` returns `{rows:[{threadId,matches:boolean|null}],revision,coverage:'complete'|'partial'|'unknown',message,refreshAt}`. Exactly one row per requested thread; no duplicates/unrequested rows. Null means unresolved. `complete` forbids null rows. `partial` can include known positives and negatives but requires the consumer to disclose coverage. Absence of topic evidence is unresolved. Invalid/deleted choices fail the read rather than becoming an empty selection.

`threadFiltersValuesV1({viewerKey,dimensionIds,threads:[{id,projectId,parentThreadId}]})` reads actual display values, independent of selected filter conditions. The output is `{rows:[{threadId,cells:[{dimensionId,values:[{id,label}],state,message}]}],revision,refreshAt}`. Exactly one row for every requested thread and one cell for every requested dimension, with no duplicate or unrequested IDs. Duplicate requested IDs and duplicate values in a cell are rejected. Single-valued dimensions return at most one value.

Cell state is `known`, `partial`, `unknown` or `not-applicable`. Known empty means confirmed None; unknown/inapplicable cells must be empty. Partial values are confirmed positives with incomplete coverage, never an assertion that omitted values are absent. Partial empty is displayed as Unknown. A non-null message explains coverage or inapplicability. No arbitrary HTML, components, links, functions or provider rendering code crosses the boundary. Output objects tolerate additive metadata; enum changes require a new value wire version. Choice IDs retain exactly their filtering meaning in column values, so a displayed value can be selected in the same attribute's filter.

`registerThreadAttributeSupplier` and `createThreadAttributeHandlers` require dimensions, choices, match and values together, and advertise valueVersions. The original filter-only helpers and methods remain source/wire compatible. New consumers call `describeAttributes`, decode filtering versions before dimensions, and check valueVersions includes1 before calling values. A legacy supplier remains filterable with clearly unavailable column data; no values are inferred from the selected choices or matches. Installing a new combined supplier adds its filter and column without host-specific code.

Value requests use the same200-thread,16-dimension,16-value-per-cell and input/output byte limits, transport client and admission queue as filter reads. `boundAttributeValues` can retain a positive prefix within the response budget; omitted values mark the affected cell partial or unknown and do not become known None. Oversize metadata still fails. Consumers batch by supplier and selected dimensions for their visible result page; do not fetch each cell, scan a complete corpus to paint a column, or start a background collector. Consumer page work is bounded separately from supplier scan budgets. Failure is isolated per supplier; identity/session/census keys fence stale results. Requested deadlines are collection-level and paused while hidden.

The consumer intersects conditions (AND); within one condition `any` means OR and `all` means AND. No general expression language, storage or background scan is introduced. Native machine and existing native filters remain consumer-owned and intersect with contributed results.

Viewer identity is attribution and an explicit personal-data lens, not authorization. Suppliers return data suitable for this trusted shared deployment; credentials/source access stay supplier-owned. Personal results and all caches are fenced by actual actor session plus viewed subject. Read handlers do not need to impersonate the viewed person.

Published per-call bounds: 16 dimensions, 100 choices, 16 selected values, 200 requested threads, 64 KiB input, 256 KiB response, 16 KiB describe. Dimension IDs use `[a-z][a-z0-9-]{0,63}`; opaque choice IDs are at most 4096 UTF-16 units. Labels are at most 512, help text 1000. Inputs are recursively strict; outputs tolerate additive fields at every evolving object. Changing closed enum meaning requires a new wire version. Raw output size is checked before DTO stripping; JSON is already parsed in the transport, so this is not a pre-allocation bound.

The owner-bound client settles locally within 5 seconds and bounds its serialized queue to 32 calls and retains one raw-call admission slot until the underlying SDK call settles. Abort fences results and asks for cancellation; it does not prove remote work stopped. No automatic retry after timeout. Suppliers must independently bound their own work. Refresh/new generation starts a new request only through the same retained client. Remote errors propagate; discovery ignores only verified `404 unknown_method` and isolates other supplier failures.

Consumer discovery calls `plugins.list` once per pass, probes running plugins with concurrency four, and admits at most 256 plugins per pass, disclosing truncation. Triggers: filter open, explicit refresh, focus/reconnect or plugin lifecycle. No healthy polling. Consumers keep unavailable selected filters active and suppress unverified rows rather than displaying the full census. Batch revisions must agree or the whole condition is retried by explicit refresh. `refreshAt` requests one collection-level deadline, paused while hidden, for cases such as snooze expiry.

Entries: root (Zod only), `/bb` (injected SDK, type-only SDK dependency), `/testing` (source conformance). No React dependency. Source conformance, host fake tests, package pack tests and live composition proof are separate evidence levels.
