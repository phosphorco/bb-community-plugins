# Inbox rows v1

Inbox owns root/visibility/archive/lifecycle validation, identity binding, indexed source reads and canonical sender/body models. The package owns bounded DTOs, fixed RPC methods, injected registration/client adapters and conformance. A host owns discovery (listed plugins plus fixed describe), one shared hydration resource, navigation, selection, fallback, error isolation, freshness and close cancellation. No feature storage, React renderer or polling is provided here.

`METHODS.describe = inboxRowsV1Describe`, null input. Negotiate the tolerant protocol/versions envelope before parsing v1 details. `METHODS.read = inboxRowsV1Read` takes `{version:1, occurrences:[{key,threadId}], archiveMode:'active'|'include-archived', viewAs?:string|null}`. There are 1–16 occurrences; duplicate keys are invalid, distinct keys for the same thread are allowed. Omitted/null viewAs selects the actual actor through Inbox's existing identity binding; a non-null subject selects a read lens, never a new actor.

Response `{version:1, ownerKey:string|null, revision:string, rows:[...]}` echoes the resolved subject and source snapshot revision. Every requested occurrence appears exactly once with the same thread ID. A ready row is `{key,threadId,state:'ready',revision,data:RowData}`; an unavailable row has `state:'unavailable',reason` (not-found/not-top-level/excluded/timeout/source-error/oversize). Ready data threadId must match. Non-null requested subject must echo exactly. Missing and unsolicited occurrences fail the client boundary.

RowData contains `v:1,threadId,title,groupPath,tags,tagOverflow,owners,ownerOverflow,ownerOverflowLabel,participants,participantOverflow,senderDescription,status:{tone,label},time:{at,text,title}`. Face entries contain `{key,name:string|null,imageUrl:string|null,label,external:boolean}`. Ordered owner and participant arrays each contain at most two portraits. Missing owner profiles retain a visible unknown owner. Owners are always shown in hosted search. Owner keys are removed from participants; participant duplicates collapse in canonical order. Overflow represents remaining canonical identities. Attribution and recent-sender descriptions follow native Inbox. Status is the thread's own lifecycle/attention, never a family aggregate. Time includes an absolute epoch ms and preformatted text; inert bodies schedule no updates.

Inputs are strict at all boundaries. Outputs are additive at every evolving object boundary, retaining unknown fields. Version 1 enums are closed. Changed meaning/input requires a new wire version and fixed methods. Canonical `JSON.stringify` UTF-8 bounds are checked before schema decoding (parsed transport JSON, not raw HTTP/preparse allocation): input 16KiB, describe 2KiB, each complete presentation stamp `{pluginId:ROW_PLUGIN_ID,schema:ROW_SCHEMA,data}` 4KiB, response 60KiB. Presentation depth remains below context-recognition's depth-eight limit. Oversized stamps become unavailable individually without removing portraits. If the complete batch exceeds 60KiB, ready rows become unavailable in reverse occurrence order until it fits. A malformed row becomes unavailable; no malformed ready stamp reaches the host.

Supplier deadline 3500ms; caller deadline 4500ms, below hosted owner's 5000ms. Supplier registration admits at most two in-flight source reads, no queue; a noncooperative source continues occupying its slot after timeout. One client admits one read at a time; cancelled/nonsettling calls do not open additional remote work. Caller abort fences local delivery, not proof of remote cancellation. Source adapters must respect signals between bounded stages. ID reads deduplicate <=16 IDs; source repeats explicit parent and lifecycle-owner root checks, hidden/deleted/archive checks. Unknown lineage is unavailable. No full owner/lifecycle tables or family traversal. Sender history <=25 events/ID, concurrency <=2; profile keys are batched, <=200 per call. Supplier-specific total profile and table bounds belong in its conformance evidence.

Inbox registers `inbox-sidebar-nerd/thread-row@1` lazily in its content-script context, with `methods:[inboxRowsV1Read]`. `assertRowPresentation` rejects missing/mismatched read allowlists even on permissive hosts. Host creates one owner-bound presentation client from that exact negotiated entry, validates the response, then renders each data stamp/revision through context-recognition 0.5.2. The actual shared body is inert: no per-row proxy, root Inbox, controls, observers or timers. Host owns role=option, stable accessible name and usable fallback. Registration disappearance or renderer/source failure must preserve those host responsibilities.

Root and /bb contain no SDK runtime imports; /bb injects registration and transport. /testing uses the public SDK fake host and invokes the real registered methods. The /testing entry uses the SDK testing entry and its documented optional testing peers (better-sqlite3, cron-parser, hono). Inject createHost to reuse an installed SDK fake host and its SQLite adaptation; the default uses the package-resolved SDK. Package tests and supplier conformance establish source behavior only. Actual browser/body parity, packaged leaf resolution, reload and CSS proof remain adopter obligations.
