# Packaging

The package publishes five explicit browser ESM entries: root, `/events`, `/bb`, `/testing`, and `/testing/react`. The build emits those entries with Bun 1.3.14 and declarations with `tsc --project tsconfig.declarations.json`. Runtime packages and optional peers remain external. Sibling public entries remain external so production code and conformance helpers share emitted modules. No source aliases or generated `dist/` files belong in the source package.

Runtime dependencies are Zod 4.6.7 and exact `@phosphorco/bb-context-recognition` 0.5.0. Context Recognition supplies the structural identity and presentation-reference facilities. Its 0.5.0 public release is sufficient for this package's surface; the conditional gallery path that needs empty-method/generic-fallback registration behavior requires a minimal Context Recognition 0.5.1 author release. That follow-up is not a dependency here and does not authorize importing a dirty workspace kit or installing an unreleased version.

`/` (root), `/events`, and `/bb` declaration closures must remain structural and free of SDK and React references. `/testing` and `/testing/react` may use their entry-specific SDK, React, React DOM, and jsdom peers; those types must not leak into the first three declaration closures. All peers are optional at package level because the production structural entries do not require the test/UI peer set. Consumers importing an entry that uses a peer must provide its compatible peer. The selected SDK's own root declarations import React types even for DOM-free testing: `/testing` needs the SDK's `@types/react` declaration peer, while React runtime, React DOM and jsdom remain absent in that consumer.

The development SDK pin selects the installed 0.6.52 Phosphor artifact for local authoring. Package and source dependency pins are reviewed before registry release. `npm run test` uses declared Bun1.3.14; `npm run typecheck` and `npm run build` check source/emission. `npm run verify:packed` packs once and installs that archive into independent disposable core, SDK-testing and UI-testing npm consumers. The core uses registry CR0.5.0 with SDK/React/DOM/jsdom absent; testing requires the actual selected SDK archive and its declared testing/type peers. All consumers typecheck emitted declarations with skipLibCheck:false and execute public imports/registered adapter or real content-script/CR-host source cases. The verifier cleans exact scratch on success/failure and reports package-owned fixtures separately from actual adopter/live/publication proof. `BB_TURN_RESULTS_PACKED_MODES=core` narrows proof explicitly; `BB_TURN_RESULTS_SDK_ARCHIVE` can identify the separately verified selected artifact. Neither overrides an adopter's manifest.

The build externalizes Zod, Context Recognition public imports, SDK imports, React, React DOM, jsdom, and sibling public entries for all entry builds. Production entries are emitted with production JSX settings and no bundled peers. Build, typecheck, package tests, packing, publication, consumer adoption, and live host behavior are distinct evidence gates.
