# BB Turn Results protocol 1

This is the implemented development contract; release and adopter proof remain separate. Package semver is independent of wire version. Changed factual meanings require a new protocol or method.

| Supplier owns | Contract owns | Consumer owns |
| --- | --- | --- |
| Source receipts and binding, policy/access, durable journal/cursors, current availability, read-only enrichment and local work bounds | Data codecs, fixed methods/version negotiation, exact correlation, canonical byte admission, owner-bound clients and source conformance helpers | Demand/discovery scheduling, durable sparse observations and coverage, grouping/contention, captions, pane placement, packing and resource lifetimes |

Attribution is not permission. Suppliers return only information suitable for every user in this trusted shared deployment; caller/plugin identity cannot bypass source access policy. Nothing here retries or initiates an external operation. Aborted requests fence local results; they do not prove remote work or a previously dispatched effect stopped.

## Entries and reusable content

Root is data-only; `/events` and `/bb` have structural ports without SDK or React declaration/runtime dependencies. Test entries explicitly require their SDK/UI peers. CR owns the sole presentation realm, registration generations/tokens, loaders and owner RPC binding. There is no new registration system, production React entry or gallery implementation import.

`ContentPresentation` contains fallback, optional existing CR presentation reference and optional advisory layout. `ContentBlock` adds referent identity and optional file/URL/thread navigation, with no event, tool call, outcome or action caption. `Resolution` composes content with occurrence identity/proof, knowledge and gallery span request. A reference's current state is not an action receipt. Consumers decide placement/space and preserve accessible data/navigation when a renderer fails or is disabled. Compact/expanded/full-width is a preference, never an entitlement. A thread reference describes the thread itself; automatic result enumeration/full-brief embedding is not implied.

Fallback discriminants are image/file/link/preview/card. Text is bounded plain data. Image alt text is required; leases are optional ephemeral HTTP(S) or origin-relative serving metadata, never artifact identity. Primary host-file navigation remains outside CR's narrower navigator. Actual host file preview uses public explicit target/location-null intent; source navigation returns provenance without claiming unavailable exact-row seeking. A thread target opens a thread without inventing an event.

## Wire admission and compatibility

Every RPC input is recursively strict, except Describe accepts ignored bounded JSON and clients send null. All raw inputs are admitted before DTO decoding. Evolving output objects accept unknown extensions; raw unknown JSON is byte-admitted **before** version decoding/normalization. V1 decoding ignores unknown DTO fields and persists/echoes the complete normalized v1 identity, allowing strict later input. Unknown extensions cannot rename a claim. `lookup` and presentation/source JSON data are deliberate JSON values, not unbounded DTO extensions. The SDK transport has already parsed JSON; these checks cannot cap raw network/pre-parse allocation.

Evidence, canvas, knowledge and route discriminants are closed. Semantic result kinds are open namespaced strings. Unknown diagnostic feed-reset reasons normalize to source-error. Unsupported versions do not decode capabilities. Describe `[1]`, `[1,2]`, `[2]`, empty and malformed inputs are distinct negotiation cases.

| Bound | Scope |
| --- | --- |
| 262,144 canonical UTF-8 bytes input; 65,536 response | Entire RPC, including unknown/additive data before decoding |
| Canonical JSON depth32; presentation depth8/4,096 bytes | Plain finite JSON only; no accessors, functions, cycles or arbitrary objects |
| 32 selected events; 16,384 combined text bytes/event; 65,536 bytes/event | Recognition input; image result/prompt/base64 omitted before selection admission |
| 64 candidates/page; 32 Resolve identities or feed rows | Sources honor smaller requested count and byte bounds |
| 4,096-byte identity; 1,024-byte lookup/sourceState; 16 sites; 8 URLs | Complete normalized immutable identity and sparse source state |
| IDs256 UTF-8 bytes; member128; cursor512; path/URL4,096; key1,024 | Well-formed Unicode, no controls; member has deterministic restricted grammar |
| Artifact identity follows CR's public identity codec | CR provider/kind grammar and id<=2,048 characters, additionally inside identity's4KiB bound |
| 500ms Describe/recognize, 1,500ms client Resolve/feed | Each call, clamped by one optional absolute overall deadline |
| Source Resolve/feed<=1,300ms, recognize<=500ms | Independent registration deadline/signals; work owners must bound underlying reads |
| Four discovery lanes, 3s slice, 32 attempted participants/slice, 256 metadata rows | Continuation visits supplier33; excess metadata explicit capacity; no polling |

Native raw page allocation, source storage, media decoded-byte limits, gallery scheduler/storage transactions and window canvas limits have separate owners. This package does not implement the gallery's database or promise all historical evidence can be recovered. Bounded event windows consume only reliable same-thread ascending prefixes; gaps count against budgets, suffix debt is preserved, and the caller must persist refs/gaps/progress atomically.

## Methods and participants

`turnResultsDescribe` returns protocol `bb-turn-results`, supported versions and aggregated capabilities. A supplier advertises revision, bounded unique kind descriptors, recognition/feed support and Resolve. Descriptors include neutral/confirmed plain labels, specificity, member derivation version and supported equivalence namespaces. Consumer role advertises invalidation. Registration validates exact handler/role parity and snapshots capabilities/handlers. Listed target id selects every cross-plugin call; advertised namespaces never choose an RPC owner.

`turnResultsV1Recognize` is pure: explicit selected event window/context plus page cursor/limit yields candidates and complete/continued/truncated coverage. No source I/O, clock, randomness, storage or mutation belongs in recognition. Digests cover all selected evidence except the digest itself. A candidate echoes the exact native source, digest and in-field UTF-16 sites. Generic link sites select actual URLs; they never confirm an external operation. Continued pages emit a candidate and advance the cursor. A finite truncation records a gap. The optional cursor helpers bind revision/window digest/ordinal without a secret or clock; suppliers still own finite member enumeration/progress.

`turnResultsV1Resolve` accepts 1..32 complete normalized identities in one thread and `maxOutcomeBytes=resolveOutcomeBudget(N)`. It returns exactly one indexed/digested outcome per request, no invented identity or cursor. The full identity occurs once inside resolved value. Both wrapper digest/index and full canonical identity are checked. Foreign/duplicate/missing outcomes, changed identity or over-budget raw fields are incompatible.

`turnResultsV1Enumerate` is an optional source-owned thread/range feed. Full upserts contain identity/proof and can bootstrap a late operation without prior recognition. Changes also include source-expired and explicit retraction. Every row matches requested origin range, advertised kind and epoch. Snapshot captures H, scans stable operation/member keys, then catches changes after H; rows seen newer than H are repaired idempotently by journal catch-up. Changes are ordered by source revision, caught-up empty pages retain a cursor, and settled means current through that head only. Cursor<=512 bytes, scope/owner/epoch/phase bound,15-minute expiry, retention gaps/reset explicit. Source journal survival, capacity and canonical native association remain supplier responsibilities, not claims established by a wire decoder.

`turnResultsV1Invalidate` is a read-only dirty hint sent to an explicit consumer target. It includes supplier id, thread, revision and up to32 affected refs or thread. Source id differs from target consumer. It neither inserts a receipt nor replaces source revision; consumer admission decides dirty/not-admitted/obsolete. No trusted-caller ACL or automatic source retry is added.

Discovery calls public plugins.list once per invocation, running/degraded only, four concurrent bounded Describe calls and stable listed-owner order. It returns per-source failures and unvisited continuation; it does not discard healthy participants or permanently exclude supplier33. Metadata above256 is an explicit capacity limit. A caller lifecycle/generation owner aborts superseded passes. Mount, explicit refresh, reconnect and plugin lifecycle are triggers; no polling loop is installed.

## Identity, evidence and historical truth

SourceRef is actual stored thread/turn/event/seq/item completion identity, never a provider hint or nearest/current turn. ClaimKey is canonical `[listedOwner,thread,event,member,kind]`; source revision is stored alongside. Member is stable original order or source operation id, never reply order/status/destination alone. ResultIdentity persists artifact, equivalence, classification, evidence sites/digest and bounded lookup; later Resolve cannot require an unretained secret or ephemeral locator.

Equivalence grouping is separate from storage. Same source-backed typed group with multiple owners is contested; the consumer keeps all claims and displays neutral inspectable data, not an arbitrary success/custom renderer. PR-open/review kinds remain separate on the same artifact. Generic display suppression requires the exact same source event/site coverage and canonical URL; it never deletes a claim or deduplicates arbitrary hrefs. Helpers require previously admitted identities/sites; the consumer must retain validation provenance.

Proof discriminants are native-image, native-command, native-tool-observation and source-owned initial-operation. Native source resolve verifies actual completed fields; selectedDigest is integrity, not authorization or external success. Command-succeeded requires exit0 and actual native success; an address observation can survive later command failure. External GitHub/Slack success requires the source-owned initial receipt and canonical binding, not a plausible link or wrapper print. Both initial-operation and late feed keep the original occurrence. Slack original/inspect/duplicate/outer/chunk association rules belong to its real source adapter and remain a separate adoption gate.

Confirmed/failed knowledge requires immutable OutcomeEvidence: observation, external-success or definite-failure as appropriate. Availability, source status, coverage and freshness are separate facts. Dead-letter exhaustion that an operator can deliberately retry is unknown knowledge; retrying the same operation then delivering advances the same original result normally. The gallery never retries/sends. Ambiguous dispatch/cancellation cannot establish definite failure. Terminal evidence changes require a correction naming the prior outcome digest; cross-epoch loss cannot erase retained terminal truth. `checkResolutionTransition` checks these bounded snapshots; persistent correction history/replay is consumer-owned.

The complete normalized terminal evidence (including `recordedAt`) is immutable without that correction. Original proof binding is immutable at every knowledge state: source/digest, initial receipt/digest/operation/binder/tool, and native assertion/exit/tool facts. An outcome correction cannot rename the operation; a distinct operation needs its own identity. The sole monotone optional proof enrichment is native-image `artifactDigest` absent → known; once known it cannot change/disappear. A conflicting higher revision throws incompatible in the same epoch and returns revalidate across epochs. Stale revisions remain stale. Initial-operation proof requires typed specificity and typed-receipt basis. Native image requires typed/native-completion; native command accepts command-output/text-link, generic only text-link/address-observed; native tool observation accepts typed-receipt/text-link, generic only text-link/link-observed. Generic observations cannot certify an external action, including feed-only bootstrap.

## Public method faults

Registered adapters return method failure as `{protocol:'bb-turn-results-fault',version:1,method,code}`. The method is one of the five public method names and must equal the requested method. Closed codes are timeout, incompatible, aborted, stale, source-error. The complete raw fault, including additive unknown fields, is limited to 512 canonical bytes before normalized decoding. Unknown fault version/code or wrong method is incompatible. A fault replaces the entire method response; it never supplies result outcomes, availability, a cursor/progress acknowledgement or proof that dispatched source work stopped. Clients decode faults before describe/result/page correlation. Exceptions, messages, stacks and private classes are not a wire protocol. No automatic retries occur.

Source deadline/lifetime/output-correlation failures are converted into these bounded data faults inside the registered handler. Unexpected source exceptions use source-error without exception text. Native input-validator failures remain native HTTP invalid_input (400), unauthorized 401/403, unavailable 503, and unwrapped handler failures remain handler_error (500) → source-error: their lost exception subtype is not guessed. The testing adapter translates the actual SDK fake-host boundary's known top-level codes to native HTTP status/body, while successful fault JSON traverses unchanged. Local caller cancellation/deadline/current fences remain independently enforced. Output faults never relax successful Resolve's raw-byte/exact-outcome admission; method failure does not fabricate unavailable/unrecognized identities.

Source handler execution includes the public builders/codecs: their local ResultsContractError, JsonAdmissionError and ZodError become incompatible before JSON fault serialization. This classification uses typed local failures, never wire class preservation or message matching. Arbitrary source/I/O errors remain source-error. Returning invalid output and throwing a known contract failure while constructing that output have the same public incompatibility policy.

Origin host recorded/unknown is separate from verified/candidate/unknown current artifact location. Current thread environment is not historical execution proof. Missing/expired files or stopped previews affect availability, preserving retained historical receipts. Preview address, process started and HTTP-ready service are distinct source evidence states; no viewer-localhost derivation or port exposure occurs here.

## Exact Resolve budgets and progress

Reserve1,024 bytes for response envelope/array punctuation. B(N)=floor((65,536-1,024)/N): N1=64,512; N8=8,064; N32=2,016. Every serialized outcome including additive fields/correlation must fit B(N), compact nonresolved outcomes<=512, entire response<=65,536. `buildResolveOutput` validates source proposals, normalizes the echoed identity, measures exact escaped UTF-8 bytes without retaining a huge JSON string, and validates the aggregate/envelope. It does not truncate required evidence/routing facts.

Required resolved outcome larger than B(N) but<=64,512 becomes budget-deferred with exact neededBytes. Client commits successful entries and retains only deferred debt. Deferred M>1 uses ordered contiguous floor(M/2),ceil(M/2) halves; a sole deferred identity goes directly to singleton. Recompute budgets, never repeat the impossible parent. Odd counts3/5/7 strictly decrease to singleton, at most3 splits from8 or5 from32. A singleton>64,512 is compact oversized, a named coverage/admission gap parked until source revision/change or explicit user retry. It is not source failure, unrecognized or permission to increase the wire cap. Storage cursor/debt application must be atomic and bounded by the consumer's transaction limits.
